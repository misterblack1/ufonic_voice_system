# SPELL and UFDIAG

Two programs for the Ufonic card, in 6502 assembly for ACME.

- `spell.asm`, SPELL, the five modes of the 1978 Speak & Spell, speaking
  through the card with the original's own speech.
- `diag.asm`, UFDIAG, a bench diagnostic for the card.

`common.inc` holds the card driver both share. `hgr.inc` and `font.inc` draw
SPELL's hi-res screen. `words.inc` is the word list, generated by
`mkwords.py` from the card image. `hello.bas` is the disk's greeting program.

## Building

The top-level `build.py` is the usual way in. This one is the second half of
it, for when a card image already exists:

```sh
python build.py card.bin card.txt out.dsk
```

It checks the card image with `../speech/ufonicfeed.py`, generates
`words.inc`, assembles both programs, tokenizes `hello.bas`, and writes them
and the card image onto a copy of `masters/dos33_blank.dsk`. Intermediate
files go to `build/`. `tools/dskput.py` and `tools/basic_tok.py` do the disk
and BASIC work.

## Disk layout

The card image sits on tracks 18 to 33. Each track holds 4 KiB of card RAM with its sectors in
descending order, sector 15 at the lowest address, the same layout the
original courseware uses. See `../card/README.md`.

## SPELL

`BRUN SPELL`. It looks for the card in slots 1 to 7, reads tracks 18 to 33
through RWTS, writes them into the card and reads them back to check. The
load takes about 16 seconds. With no card, or a card that fails the check,
it runs in text only mode: each phrase is printed on the SPEAKS line in
place of speech. The footer says which.

### Keys

| Key | Action |
| --- | --- |
| A to Z | Type a letter |
| Return | Submit the answer |
| Left arrow | Erase the last letter |
| CTRL-S | Spell mode |
| CTRL-Y | Mystery Word mode |
| CTRL-O | Secret Code mode |
| CTRL-L | Letter mode |
| CTRL-I | Say It mode. Tab sends the same code on a IIe |
| CTRL-G | Go, new game in the current mode |
| CTRL-R | Repeat, speak the current word again |
| CTRL-C | Clue, help that depends on the mode |
| CTRL-Q | Quit to DOS |

### Modes

- Spell. The power-on mode. The word is spoken and the player types it.
  Two tries a word, ten words a game, then the score is spoken. After a
  second miss the correct spelling is spoken letter by letter. Clue gives
  the first letter, and a clued word does not score.
- Letter. The word is spoken with one letter blanked. One key answers. Two
  tries, ten rounds.
- Mystery Word. Hangman against the speaker. Each wrong letter adds an X,
  five ends the word. A clean solve scores one.
- Secret Code. Each letter typed shows coded in the display. The code is
  Atbash, A for Z, B for Y and so on, so typing a coded message shows the
  plain one. The toy's own code table is not known, so this is a stand in.
  No score.
- Say It. Listening practice. Words play in turn and any letter moves on.
  No score.

### Talking to the card

One routine speaks everything. It builds a queue, waits for the card to
read $5F at $Cn00, rewinds the DRAM counter, writes the queue through
$C0n0 and strobes GO:

```
DRAM[$0000] = $80          queue command
DRAM[$0001] = count        up to 63
DRAM[$0002+] = indices     16-bit, high byte first
```

The ROM reads each queue entry high byte first, the same order as the
command and parameter bytes. Only the vocabulary table is low byte first.

GO does not change $Cn00 at once. The ROM sees the attention line on its
next poll and only then shows Busy, $DF. So after GO the routine first waits
for $Cn00 to leave $5F, with a short timeout in case the card has already
finished, and only then waits for $5F again. Waiting for $5F straight after
GO returns before the card has started.

Screen changes that belong to a spoken line run after that wait, so picture
and sound stay together. If the card stays busy for about 30 seconds the
footer shows CARD STUCK and SPELL drops to text only mode.

## UFDIAG

`BRUN UFDIAG`. It shows $Cn00 for every slot and picks the first that
reads idle, $5F, or failing that the first that reads busy, $DF. S sets the
slot by hand.

| Key | Test |
| --- | --- |
| 1 | Talk: read Port B, then write and read back 256 DRAM bytes |
| 2 | Play the ROM test tone and time how long Busy stays up |
| 3 | ROM checksum through command $1C. A good ROM sums to $F0 |
| 4 | DRAM test over all 64 KiB, six patterns |
| 5 | DRAM retention, write, wait 20 seconds, read back |
| 6 | Reset the card |
| 7 | Send any command byte and trace Port B |
| A | Run tests 1 to 5 |
| S | Set the slot |
| Q | Quit to DOS |
